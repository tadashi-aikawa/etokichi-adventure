# RPGマッププロトタイプ設計

## 目的

既存のバトルを残したまま、正面見下ろし型のマップで移動・会話・ステータス確認・バトル往復を検証する。具体的な舞台設定やシナリオではなく、今後マップを追加できるデータとシーンの境界を作る。

## 採用方針

- 視点は正面見下ろし型。Tiledの直交グリッドを使う
- 移動はマス単位ではなく4方向の自由移動
- PCとスマートフォン横画面を同じゲーム状態へ接続する
- エトキチとNPCにはバトル用画像を流用せず、マップ専用の4方向歩行素材を用意する
- 会話は複数ページ・選択肢・フラグによる再会話時の変化を扱う
- 永続セーブは作らないが、ワールド状態はJSONへ直列化できる形を保つ

## 状態の境界

ゲーム全体は次の2層へ分ける。

1. `WorldState`: タイトル・マップ・バトルをまたいで残る状態
    - 現在のシーン
    - マップID、座標、向き
    - 操作中キャラクターIDと、広場の5スロットにいるキャラクターID
    - 会話・イベントフラグ
    - 進行中のエンカウントと直近のバトル結果
2. バトル内部状態: 既存の `game.js` が試合中だけ保持する状態
    - ライフ、ガッツ、残り時間
    - 技演出、操作ロック、AI判断、時間制状態の期限

バトル内部状態はアニメーション時刻を多く含むため保存対象にしない。マップからバトルへ入るときに操作中キャラクターを自分側、会話相手を敵側とする`WorldState.activeBattle`を作り、勝敗確定時に結果を記録し、退出時に指定されたシーンへ戻る。操作変更では会話相手がいたスロットへ直前の操作キャラクターを置くため、何度入れ替えても6人が重複・消失しない。

```text
title ───────→ battle ───────→ title
                 ↑
map ─────────────┴───────────→ map
     位置・会話フラグを保持     結果を反映
```

## 実装順序

1. `src/game/game-session.ts` でシーンとワールド状態の契約を固定する
2. TiledのTMJ/TSJを読み、PixiJSへマップ用コンテナを追加する
3. 移動・衝突・カメラを接続する
4. 会話・ステータスをワールド状態へ接続する
5. 既存バトルの開始・結果・退出をゲームセッションへ接続する
6. スマートフォン横画面の操作と統合確認を行う

## Tiledデータ規約

正規データは`assets/maps/*.tmj`と`assets/tilesets/*.tsj`に置く。どちらもJSONなので、Tiled GUIを使わずAgentが直接参照・編集できる。Tiledで開いて編集してもよいが、プロトタイプの実行にTiled本体やCLIは必要ない。

- 有限の`orthogonal`マップ、固定長のタイル配列だけを使う
- TMJは外部TSJをちょうど1つ参照する
- マップとタイルセットのタイル寸法を一致させる。プロトタイプは64×64px
- 反転・回転フラグ付きGIDは使わない
- マップのカスタムプロパティ`mapId`をゲームセッションのIDと一致させる
- 次のレイヤーを必須とする

| レイヤー | Tiled型 | 用途 |
| --- | --- | --- |
| `ground` | Tile Layer | 地面・道・建物・水面など、キャラクターより背面の描画 |
| `foreground` | Tile Layer | 木の葉や花など、キャラクターより前面の描画 |
| `collision` | Object Layer | 通過できない軸並行の矩形 |
| `actors` | Object Layer | actorのpoint。`entityId / characterId / eventId / behaviorId`をカスタムプロパティに持つ |
| `entrances` | Object Layer | 出入口と初期地点のpoint |

`src/game/tiled-map.ts`がこの規約を検証し、描画用レイヤー・衝突矩形・NPC・入口へ変換する。不正データは読み飛ばさず起動時にエラーとする。移動はキャラクターの足元へ寄せた当たり判定をX軸、Y軸の順に解決するため、見た目が水や障害物へ入り込まず、壁へ斜めに入力しても壁沿いの軸は動ける。

`foreground`のタイル、NPC、プレイヤーは足元のY座標で描画順を決める。前景タイルはTSJのタイルプロパティ`depthY`（0〜タイル高）でタイル上端からの切替位置を指定でき、省略時はタイル下端を使う。背の高い花は根元より上へ基準を寄せ、キャラクターの顔を長く隠さないよう素材ごとに調整する。木タイルは見た目を問わず通行不可とし、通れる場所を作る場合は道や入口として視覚的にも区別する。

## プロトタイプ用マップ素材

`prototype-plaza.tsj`は`prototype-plaza.svg`を64px×8タイルのアトラスとして参照する。SVGは原本兼配信用で、ViteがベースURLを解決する。量産段階でラスター素材へ移行する場合も、TSJの`image`と寸法を更新し、TMJのGIDとレイヤー規約は維持する。

## マップ専用キャラクター素材

バトル用の大きなポーズ画像は流用せず、`assets/map-characters/<ID>/`へマップ専用素材を置く。

- `source/walk.png`: 編集・再変換用のRGBA原本
- `walk.webp`: PixiJSが読む配信用WebP。縮小表示を前提に品質88、アルファ品質100とする
- シートは3列×4行。幅は3、高さは4で割り切れること
- 行は上から`down / left / right / up`
- 列は左から`左足前 / ニュートラル / 右足前`
- 停止時は中央列、歩行時は`左足前 → 中央 → 右足前 → 中央`を繰り返す
- 各ポーズは隣のセルへはみ出さないよう、透明部分を含めて1セル内へ完全に収める
- 3コマのキャラクター中心軸と足元を揃え、進行方向と直交する揺れが出ないようにする
- 背景は実アルファ透過にする
- 生成AIのシートはセル境界と足元が保証されないため、完成品として直接配置しない

生成画像から原本PNGと配信用WebPを作るときは、次の正規化ツールを通す。このツールはクロマキーの純緑近傍を透過したうえで主要な12ポーズを検出し、1コマずつ切り出して418×313セルの中央・下端へ再配置する。これにより、生成画像内の見かけ上の区切りと実際のセル境界がずれていても、隣セルやクロマキー残片の混入を防げる。

```sh
pnpm map-character:normalize -- \
  <生成画像.png> \
  assets/map-characters/<ID>/source/walk.png \
  assets/map-characters/<ID>/walk.webp
```

追加・更新後は`pnpm map-character:validate`を実行する。各セルの四辺に4px以上の透明余白があることと、方向ごとの3コマで中心軸・足元の差が3px以内であることを自動検査する。この検査は`pnpm check`にも含まれる。検査後も上下左右すべての停止・歩行を実画面で確認し、欠け・隣セルの混入・進行方向と直交する揺れがないことを完了条件とする。

追加後は`src/content/map-actor-catalog.ts`へURLと表示寸法を登録する。表示寸法は元セルと同じ縦横比を保ち、正面中央フレームの不透明部分が既存キャラクターと同程度の高さになるよう調整する。Tiledのactorマーカーには`entityId / characterId / eventId / behaviorId`を設定する。フレーム幅・高さは画像寸法から計算し、3列×4行で割り切れなければ起動時にエラーとする。

## 会話イベント規約

Tiledの`actors`レイヤーに置くactorは、文字列プロパティ`eventId`で`src/content/event-catalog.ts`の宣言的イベントを参照する。actorの座標や見た目とイベントデータを分離し、同じイベントを別マップでも利用できるようにする。詳細な責務境界は`docs/rpg-map-architecture.md`を参照する。

- NPCには静的な当たり判定を置き、プレイヤーとNPCが重ならないようにする
- NPCへの接触では開始せず、正面104px以内・横ずれ56px以内で決定操作をしたときだけ会話する
- 会話開始時、NPCはプレイヤーがいる方向を向く
- プロトタイプ広場のキャラクターは「対戦する」「操作を変える」「なんでもない」の共通3択を持つ
- 「操作を変える」は操作中キャラクターと会話相手のスロット配役を交換し、ステータス表示も新しい操作キャラクターへ追従する
- 「対戦する」は操作中キャラクター対会話相手で既存バトルへ入り、結果後は位置・向き・配役を保って広場へ戻る
- 会話はノード単位で本文・次ノード・選択肢・更新するフラグを宣言する
- 会話ノードにメインキャラクターの`speakerId`があれば、そのキャラクターの既存立ち絵を会話ウィンドウ上側へ表示する。非メイン話者や`speakerId`未指定時は立ち絵を出さない
- 操作キャラクターの立ち絵は画面左側、会話相手の立ち絵は画面右側へ寄せる。会話枠は台詞量や選択肢の有無によらずPC 305px・スマートフォン横198pxの固定高とする。画像自体はトリミングせず、キャラクターごとのY座標で足元を手前の会話枠へ隠してバストアップ感を保つ。PCでは表示領域の44%幅、スマートフォン横画面では操作レール内の43%幅を上限とし、キャラクターごとに倍率とY座標を調整する
- メインキャラクターへ話しかけた直後は、操作キャラクターの発言、会話相手の応答、行動選択の順で進む。導入会話は両者の組み合わせごとに変え、クロボシの発言は人間の言葉にせず鳴き声で表現する
- 選択結果と会話完了は`WorldState.flags`へ保存し、同じNPCとの二度目の会話開始ノードを切り替える
- 会話・ステータス表示中はマップ入力をロックし、PCキーと画面ボタンを同じ操作関数へ接続する

プロトタイプのPC操作は、`E`・`Enter`・`Space`が決定、`M`・`Tab`がステータス、`Escape`が閉じる操作となる。選択肢は上下キーまたは画面ボタンで選ぶ。スマートフォンでは右下の「話す」「ステータス」と会話内ボタンを使う。
